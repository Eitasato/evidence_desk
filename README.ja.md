# Evidence Desk

## 概要

質問と、その答えの根拠となる資料を蓄積していくアプリケーションです。SEO対策用の記事を作るにあたり、調査資料を分類した索引を用意したくなったことが開発の動機です。

調査をするときに浮かべた問いを登録し、資料を読みながら参考になる段落や文章を記録していきます。Webの記事やコラムなどの場合はタイトルとURL・参考にしたい本文と該当箇所の見出し、論文やスライド資料などの場合はページ番号や段落番号を登録します。

また質問に結びつけた各段落には、Adopted（採用）・Pending（保留）・Rejected（却下）の判定と、判定理由のメモを残します。調査をしながら資料のアーカイブを作成していくことができます。

記事制作の参考にした資料名やURLのみならず、参考にした文章やその記載箇所を記録することで、回答の根拠となる資料にスピーディーに辿れることを目指しました。

## 仕組み

問いを起点に、回答の根拠となり得る段落や文章、それらが掲載されている資料、また本文の掲載箇所を辿れるような構成となっています。

データベースには Source・Passage・Question・EvidenceLink の4つのテーブルを用意しています。Source には資料、Passage には資料から切り出した段落、Question には問いを記録します。EvidenceLink には、どの問いにどの段落を根拠として結びつけたか、またどの判定を下したかを、理由も併せて記録します。段落はそれぞれ資料に属するので、根拠からは段落を通じて資料までたどれます。

ひとつの問いに対して複数の段落・資料を登録できることが特徴です。また、同じ段落を複数の問いに結びつけ、問いごとに異なる判定を付けることもできます。

## 設計の考え方

問いを起点に記録するという発想は、読み手のニーズをベースに記事制作をしていくという仕事のプロセスから得ました。また読書をする過程で、本の内容をどう記録し、別々の本同士をどう結びつけていくかという課題も今回のアイデアの元となっています。

却下した段落も記録することにしたのは、判断をアーカイブさせることで自身が不要と判断した資料の共通点を見出し、将来的にスクリーニング基準を設けることを想定したためです。

また資料、段落、根拠はそれぞれ関係し合っているため、資料を消すと段落および根拠も併せて消える仕様としています。資料はURLを登録するようになっていますが、書籍の場合はURLを空欄にして登録できます。

## 手元で動かす

Ruby 3.2.3 が入った環境で、次のコマンドを順に実行します。

```
git clone https://github.com/Eitasato/evidence_desk.git
cd evidence_desk
bundle install
bin/rails db:prepare
bin/rails server
```

ブラウザで http://localhost:3000 を開くと、アプリが表示されます。`bin/rails db:prepare` でデータベースが作られ、見本の質問と資料が入った状態で始まります。テストは `bin/rails test` で実行できます。

## デプロイ

アプリのデモは、Rails が生成した Dockerfile をもとに `gcloud run deploy --source .` でイメージを作成し、Google Cloud Run（東京リージョン）に公開しています。

Cloud Run はコンテナにリクエストを渡す際に、通信方式を https から http に切り替えます。そのため Rails は自分を http で動いていると認識し、https のページから送られたフォームを拒否してしまうので、`config.assume_ssl` を有効にしています。

また、Rails の起動が終わる前に届いたリクエストにエラーを返すことがあったため、起動判定に `/up` を用い、Rails が応答できるようになるまで待ってからリクエストを渡すようにしています。コンテナごとに別のデータベースを持つため、台数は1台までとしています。

## 制約と今後の課題

デモは見本として公開しているため、データはコンテナが起動し直すたびに初期の状態に戻ります。Cloud Run はコンテナを止めると中身を破棄する仕様となっており、登録したデータも削除されます。データを残して使いたい場合は、リポジトリを取得して手元で動かしてください。公開版でデータを残すには、Cloud SQL などの外部のデータベースに切り替える必要があります。

また、しばらくアクセスがないとコンテナが停止するため、最初の表示に30秒ほどかかることがあります。表示されない場合は、ページを再読み込みしてください。

秘密鍵は環境変数で渡していますが、本来は Secret Manager で管理するのが望ましい形です。Ruby はサポートが終了した3.2系を使っているため、更新を予定しています。

画面は、scaffold がテーブルごとに書き出したものをそのまま用いています。段落の登録に手間がかかることが、実際に使ってみて分かった一番の課題です。資料と段落の詳細画面を省く、根拠の一覧と問いの詳細画面の役割を整理するなど、画面の見直しを今後の課題としています。
